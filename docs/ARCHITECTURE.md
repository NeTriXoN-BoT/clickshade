# Architecture

ClickShade is C++17, with a Win32 app on Windows and a GTK3 app with explicit Linux backends. This document describes the implementation. The [settings guide](SETTINGS.md) covers user-facing behavior and the [effects reference](EFFECTS.md) the platform coverage.

The GUI thread never handles global mouse motion. Input uses Raw Input with `RIDEV_INPUTSINK`, without `RIDEV_NOLEGACY`, low-level mouse injection or synthetic movement. Selected buttons are ORed across devices. A 200 ms reconciliation timer exists only while a button is held, as a missed-release fallback only when foreground integrity makes asynchronous state readable; normal Raw Input release is handled immediately. A higher or unknown integrity level is not evidence of release. Windows move/resize loops do not count as game confinement.

Settings changes are compared by subsystem. Interface colors, extra zoom and startup changes must not restart graphics/audio or interrupt a held cursor. GUI saves and status messages are coalesced. File loading, image preparation, audio decoding and disk persistence stay out of per-movement and per-click dispatch; configuration prepares the caches ahead of use.

### Cursor ownership

The original baseline, configured released appearance, and pressed appearance are independent owned caches. Pause and quit restore the baseline, including when reverse/custom idle mode is active. `SetSystemCursor` consumes the handle passed to it, so each installation loads a fresh handle from the prepared cursor file, or makes a fresh owned copy when no file could be written. That copy is rebuilt from `GetIconInfo` with `CreateIconIndirect`, not `CopyImage`: under a larger pointer size `CopyImage` resamples through the drawn size and returns odd sizes one pixel short. Never pass a shared handle or a cached master.

Static CUR files are bounded and validated before choosing an exact or next-larger frame. PNG/DIB dimensions and hotspots are checked. Alpha images are resized and styled in premultiplied form, then written back with straight alpha, because Windows stores and draws every cursor color bitmap that way (from files and from `CreateIconIndirect` alike); masks and proportional hotspots remain consistent. Unchanged sizes are cloned without a generic resize conversion. Automatic companion discovery only selects a unique same-directory match and does not replace an explicit pressed path.

Windows draws a cursor at its nominal size times the pointer size and the scale of the monitor under it. A cursor made from one bitmap (`CreateIconIndirect`, `CopyImage`, `CopyIcon`) is stretched to that size and looks soft or blocky; a cursor loaded from a file keeps every image and Windows draws the one that matches, as it does for the installed theme. So every cursor ClickShade installs (pressed, scaled, faded, shadowed, recolored, Classic, Windows arrow, custom pair, shake sizes and animated roles that are resized or styled) is written as a multi-size `.cur`/`.ani` file holding an image at every size Windows draws it at on the current monitors, each rendered from the sharpest source: the theme's own file, or for a built-in cursor the image Windows itself draws. Windows scales the finished master, so each extra image is a multiple of the master's size; a shadow grows the artwork, so for the shadow look the artwork is built at the size that the shadow grows to each target. The original theme is restored exactly as Windows loads it, from the theme's own file where one exists. Files are written while settings change, never on a click or per input report, into a private per-engine folder, `%TEMP%\ClickShade\cursors\<process>-<tick>-<n>\`, with one `g<k>` subfolder per prepared configuration. Each written file is reopened for reading with read-only sharing and kept open while its configuration can still be installed, after checking that the reopened file (volume serial and file index) is the one just written; a mismatch is refused. That handle makes the file impossible to delete (temporary-file cleaners such as Disk Cleanup or Storage Sense get a sharing violation) or replace, and keeps every folder above it from being renamed, while `LoadImage` still reads it. The engine removes its folder on exit and, when a normal (unelevated) instance creates one, removes the folders of instances that have ended; an elevated instance never deletes by path inside folders that ordinary programs can change. Cleanup deletes only `.cur`/`.ani` files and its own subfolders and skips reparse points; the `cursors` and `ClickShade` parents stay. An administrator instance creates its own folder with a high-integrity mandatory label, so a medium-integrity program cannot write into it. If no file can be written, every cursor falls back to the in-memory copy described above, which Windows stretches as before. An animated role whose rebuilt animation cannot be loaded falls back to the scheme's own `.ani` at the chosen size, then to a still copy, so an installation never fails over a missing file.

A cursor reload after a Windows theme, pointer-size or display-scaling change restores the cursors but keeps the held-button bookkeeping, so a held button stays pressed and its release still arrives from a known device. Setting broadcasts that cannot change cursor images (work area, accent and theme colors, policy, taskbar and regional settings, screen saver and wheel settings) do not reload; `SPI_SETCURSORS` and high contrast always do. An application hiding the pointer pauses only press, pulse and shake: the configured cursors stay installed, so the pointer comes back with its scale and look and without a restore-and-reinstall flash. Startup configures the requested appearance directly and builds the default cursors only when that fails, so the artwork is prepared once.

Current-theme mode covers every system cursor role, including Help, Pin, Person and the pen. The animated busy and working roles are handled separately: copying an animated cursor keeps one frame, so each installation loads an animation file again rather than copying, press and shake effects leave it alone, and restoration reloads the whole scheme with `SPI_SETCURSORS` instead of reinstalling a flattened snapshot. A static arrow preset (Windows arrow, Classic, custom pair) over an animated arrow makes that role static, so press and shake reach it, while restoration still reloads the animated scheme. With a chosen size or a cursor look, the `.ani` is rebuilt: every frame is decoded at the target size and at each larger size Windows draws it, styled, re-encoded as a multi-size straight-alpha CUR frame, and the RIFF/ACON container is reassembled with the original rate and sequence chunks, written to the cursor folder and loaded from there. If that fails, the registered `.ani` is loaded at the chosen size, where Windows picks its own frames and stretches beyond the largest. The look is applied after inversion and magnification, so a shadow or a color is never inverted. Reconfiguration keeps each role's animated flag. The classic arrow is a vector silhouette with the classic Windows proportions rasterized at the final size, so it matches the original 32 px file and sits in proportion to every other resized shape. The local `arrow_r.cur` is used only when it holds an image of exactly the needed size; it is never resampled. An application-owned or software pointer is not necessarily a system role. Local Windows/classic assets are read from the user's OS and never redistributed. A missing profile leaves an editable error rather than killing the runtime.

### Rendering

Highlights reuse a cached DIB and move their own small click-through, non-activating windows. A shown halo moves through `UpdateLayeredWindow` with only a new origin, the same call that moves the spotlight's circle, because the compositor applies it sooner than a `SetWindowPos` move; showing and raising still use `SetWindowPos`, which is also the fallback. Click particles are bounded to eight; trails to 32. Trail styles rasterize when a stamp is created, then fade immutable pixels. Breathing is a blend-only update: about 30 times a second the cached highlight is presented again with a constant alpha between 55% and 100% on a 3.2 s cycle, at rest and in motion alike, without resizing it. The renderer samples OS cursor coordinates, never a queue of old raw deltas. It does not modify the pointer position, sensitivity or acceleration.

The halo, spotlight and lens reach the screen with the next composition, after the pointer has moved on. During steady fast motion they are therefore drawn slightly ahead. The lead is `PointerLead` in `src/pointer_lead.h`, pure arithmetic on the renderer's motion-frame samples. Speed and direction come from a least-squares fit over the recent frames that saw a new pointer position, so a mouse that reports less often than frames are drawn, or unevenly, still gives a steady estimate; a second fit over the newer part of the window detects braking and turning. The lead needs a speed above about 700 px/s at 96 DPI and is full from about 1600 px/s, fades for braking and for turns (full up to about 20 degrees, none from about 37), fades in over a few frames, and is capped in length and kept inside the pointer's monitor. A frame without a new position (an event without motion, a report that has not arrived yet) keeps the lead; a pause longer than the pointer's own report spacing counts as a stop, and the settle check then drops the lead at once, so the effects come to rest exactly on the pointer within about one report gap. A long pause, or a change of monitor or rate, starts a new history. Trails and click effects always use real positions. The headless suite `tests/pointer_lead_test.cpp` drives it with simulated 125 to 1000 Hz mice, with jitter, on 60 to 360 Hz displays.

The spotlight is a single layered window over the pointer's monitor with a monitor-sized premultiplied surface. A move restores the shade where the circle was, stamps the pre-rasterized circle at the new position and hands only the union of the two squares to `UpdateLayeredWindowIndirect` as its dirty rectangle, so a move costs about two circle areas of pixel work. Because it is one window, the compositor can never show the dim area and the circle out of step. The surface is freed as soon as the spotlight is switched off. When an application hides the pointer, every pointer effect hides with it, the spotlight and the lens included. Only when the pointer was hidden right after keyboard input (an editor while you type) do the spotlight and the lens stay where they are, so they do not flash with every word. `GetLastInputInfo` reports only the time of the newest input of any kind, not what it was. The runtime therefore tells the renderer whenever it receives mouse input (motion, buttons or the wheel, also while the pointer is hidden) through `VisualEffects::MouseInput`, and `UpdateTypingHold` starts and continues a hold only while the newest input is newer than that, so clicking into an app, scrolling or a game's mouse look never keeps the spotlight or lens on screen. The hold also needs that input to be newer than the last pointer motion the renderer saw and to have come within about 1.5 s before the pointer disappeared, and the hidden pointer must not have moved. It ends about 3 s after the last input, as soon as the hidden pointer moves, or when the pointer shows again. A video player that hides an idle pointer fails these tests and hides everything. While the hold or the key display is visible, stacking repair keeps them above other always-on-top windows.

The magnifier is a color-keyed layered host with a Magnification API child clipped to a circle or rounded square, plus an antialiased frame surface on top; both move in one batch. `magnification.dll` is loaded at run time, so a machine without it keeps every other effect, and a lens failure disables only the lens until settings change. The zoom is the child's `MagSetWindowTransform` matrix, with bitmap smoothing where Windows offers it. Creating the child costs well over 100 ms, so it is created once and later size, shape, frame and cursor changes adjust it in place. The source rectangle is the child's side divided by the zoom, centered on the pointer and clamped to its monitor. The exclusion filter accepts at most 24 windows, so it carries the lens itself, the halo, spotlight and key display, then the click rings and trail stamps that overlap the source square, newest first; a halo is never magnified. While the pointer rests the lens re-reads the screen at 30 Hz; while it moves, at the motion rate.

The key display is one rectangular layered surface holding up to three rows: a shortcut is a row of keycaps, and in every-key mode typed characters join one row that Backspace edits. Typed text comes from `ToUnicodeEx` with its no-state-change flag, using the Shift, AltGr and Caps Lock state reported with the key. Each row is rendered once into its own premultiplied buffer (signed-distance rounded panel, soft shadow, hairline rim, keycaps with a darker lower edge, glyphs rasterized by GDI in grayscale and composited as coverage), and the rows are composited with individual fades. The surface is placed on the foreground window's monitor inside the work area, anchored at its edge so a row that leaves does not move the others. Its rule gate ignores the hidden pointer (editors hide it while you type, video players and games at other times), so the renderer keeps a second `keyAllowed` flag and hides pointer effects and the key row independently.

Animation uses monotonic QPC time and phase-preserving one-shot waitable-timer deadlines. Late frames skip catch-up work. Auto pacing starts from the monitor refresh rate and adapts the animation budget from short, in-memory work averages with hysteresis. A long idle gap starts a new observation and counts as one ordinary frame, but keeps the headroom already earned, so short animations separated by idle time (a series of clicks) still add up to a recovery while idle time itself never earns any. Cached motion keeps a separate display-paced deadline. Manual limits are 30–360; no timer-resolution or display-mode change is made. Automatic/manual pacing is bounded; stationary highlights and fully expired effects need no repeating frame timer. A high-resolution waitable timer is used when available, with a normal timer fallback. No machine-wide timer-resolution request is made.

Separate blocking receiver threads install out-of-context WinEvent hooks. Their callbacks only filter and coalesce notifications; no drawing, input work, file access or foreign-window messaging runs inside them. This isolates accessibility-event floods from the input and render message loops. Stop unsubscribes on the receiver thread even under a continuing event flood.

Out-of-context WinEvent notifications cover relevant window show/reorder/location and menu lifecycle events. The renderer's stacking receiver is not permanent: it starts when an overlay becomes visible and stops 5 s after the last overlay hides, so with no effect on screen, or every visual effect off, the renderer receives no desktop-wide window or cursor location events. A failure to install it is reported as a renderer error at that moment. Overlap checks repair stacking on active frames. Own-thread events are skipped and bursts coalesced, avoiding a self-triggered stacking loop. Stacking changes never activate an overlay or bypass the common pause gate. Normal desktop z-order is not a guarantee over secure/privileged presentation layers.

### Shake and audio

`ShakeLocator` holds at most 256 turning points in logical OS coordinates. It
compresses same-direction motion, expires old samples and keeps animation time
separate from input arrivals. Published Plasma parameters and original
macOS-inspired parameters are documented in [EFFECTS.md](EFFECTS.md). No upstream
GPL implementation is copied into this MIT project.

Windows prepares at most 1/16-scale Arrow variants, deduplicates image sizes and
caps images/cache memory. Animation selects existing handles; it does not resize
images or open files per input report. A monitor-DPI cancellation must restore
engine magnification as well as controller state. Schedule the next deadline from
the timestamp of the frame actually applied, then convert that deadline against
completion time. Otherwise an API overrun can consume the terminal 1× frame and
leave the cursor enlarged indefinitely. X11 uses the same sampled-time invariant.

WAV files retain a validated source handle/descriptor and a 100 ms decoded prefix.
Each active source has a bounded window, independent of duration. The Windows
worker mixes up to sixteen voices in 10 ms chunks; each voice owns a 100 ms
prefetch ring that is topped up before a chunk is mixed so a live voice is never
padded with silence. Mouse and keyboard voices carry separate gains read per chunk.
When all sixteen are busy, a new start replaces the voice with the fewest frames
left to hear; a compressed stream whose length is not known yet counts as the
longest, and ties cut the one that has played longest.
Output is event-driven shared-mode WASAPI with automatic format conversion and a
waveOut fallback of eight 10 ms buffers, one mixing chunk each, so the writable
space it reports is exactly what a write can queue. A driver that keeps its
headers or handle keeps the buffers and the callback event until process exit.
The device closes after twenty idle seconds. Media Foundation
produces bounded stereo PCM packets and readers are destroyed before
MFShutdown/CoUninitialize/DLL release. Volume changes affect future chunks; zero
flushes that group's voices. Mouse and keyboard sounds have separate eligibility
gates: the runtime closes the mouse gate for every pause, the hidden pointer
included, and the keyboard gate for every pause except the hidden pointer, so a
hidden-pointer pause cuts only mouse voices. Stop/pause closes both gates and
pending starts before cleanup. A switched-off group's files are not opened (the
worker releases them on the settings change), so a stale or imported path is not
touched until its sounds are switched on. A mouse preview opens only the tested
button's file, a keyboard preview only the keyboard set; files a preview opened
stay open until the next reload (a path, enable or to-or-from-zero volume change).
No cursor thread waits for file decoding, playback or the GUI. An in-flight OS
codec/kernel/driver call is not a universally cancellable operation, so native
cursor restoration occurs before optional-worker joins.

Keyboard sounds and the key display register the keyboard usage with Raw Input
only while one of them is enabled. The input thread reduces each key-down to one
of four categories for the audio worker. For the key display it applies the
shortcuts-only policy, tracks which modifiers were held during a chord (so a
tapped Win or Ctrl is labelled on release while Shift+letter typing is not), and
posts the virtual key, scan code and modifier flags to the renderer, which formats
the label from the foreground window's keyboard layout. Nothing about a key is
kept once its label has faded. Both keyboard features keep working while an
application hides the pointer. A set folder provides up to six shuffled key
variants plus optional space, enter and backspace files.

### Rules and shortcuts

The common gate covers enable, engine readiness, lock/suspend/inactive desktop, real cursor visibility, explicit exclusions, and configured fullscreen-game/confinement rules. Per-app allowances bypass only the latter heuristics. Exclusions and protected/hidden states retain priority. A maximized decorated desktop window is not automatically fullscreen.

The fullscreen rule pauses only games. A foreground window that covers its monitor counts as a game when `SHQueryUserNotificationState` reports exclusive fullscreen Direct3D, when its executable is on Windows' own game list (`MatchedExeFullPath` values under `HKCU\System\GameConfigStore\Children`, read only and never changed), or when its path lies in a usual game library folder (`\steamapps\common\`, `\Epic Games\`, `\GOG Galaxy\Games\`, `\GOG Games\`, `\Origin Games\`, `\EA Games\`, `\Ubisoft Game Launcher\games\`, `\Riot Games\`, `\XboxGames\`, `\Rockstar Games\`, `\Amazon Games\Library\`, `\itch\apps\`, case-insensitive). Browsers, video players and presentations therefore keep their effects; an unrecognised game needs an exclusion. The cost stays off ordinary windowed use: the library-folder answer is cached per foreground process, the game list is read only for a fullscreen window that is not already a library game (at most once a minute, and from the click path at most once per foreground process), and the exclusive-fullscreen query re-runs on window and foreground events and at most once a second from clicks. `SHQueryUserNotificationState` is looked up in the already loaded `shell32` only once a fullscreen window appears.

Cursor visibility comes from `PointerVisible` in `src/pointer_visibility.h`. Besides a cleared `CURSOR_SHOWING` flag and touch/pen suppression it treats a null cursor (Chromium) and a fully transparent cursor image (Firefox for CSS `cursor: none`, which still reports `CURSOR_SHOWING`) as hidden. A switch to a transparent cursor while the mouse rests arrives as a cursor shape WinEvent, so it is picked up without movement. A hidden pointer hides every pointer effect, with the typing exception described under Rendering, but does not reset a customized cursor; the key display and keyboard sounds use a gate without the visibility condition.

Windows shortcuts use `RegisterHotKey` with `MOD_NOREPEAT`. Editable strings normalize to a canonical chord. Bare/Shift-only typing keys are rejected, duplicates/conflicts reported, and a failed edit preserves working bindings. Windows-reserved F12 is rejected before registration. Recording happens only in the focused settings control. No global keyboard hook or key log is used.

### Process lifetime

One instance per desktop session is enforced with a named mutex plus the settings window class; a second launch posts a show request and exits, waiting briefly for a window that is still being created. An unelevated launch cannot open an elevated instance's mutex at all (access denied), which also means ClickShade is running, so it shows that window too. The launch hands the foreground to the running instance with `AllowSetForegroundWindow`, so the window comes to the front from the tray. Administrator mode relaunches through `ShellExecuteEx` with `runas` and a `--replace <pid>` handshake, passing `--tray` and the crash-restart generation on. It opens the show/restore/quit messages and Explorer's `TaskbarCreated` broadcast through the UIPI filter, so unelevated launches still reach the elevated window and its tray icon returns after an Explorer restart. Version 4 tray icons report a click both as the raw button message and as `NIN_SELECT`/`WM_CONTEXTMENU`; only the latter act, and every add and change carries `NIF_SHOWTIP`.

For startup, administrator mode registers a Task Scheduler logon task with the highest run level at priority 4 (normal; the Task Scheduler default of 7 is below normal), but only when `ExecutableLocationProtected()` holds: the file, its folder and every parent folder are owned by Administrators, SYSTEM or TrustedInstaller; no allow entry in their permissions gives any other account or group a right to change the file or folder or to replace an entry below a parent (`OtherPrincipalCanChange`; inherit-only entries are skipped, `CREATOR OWNER` and `OWNER RIGHTS` stand for the trusted owner, and an entry it cannot read counts as a change right); an `AccessCheck` with the user's standard (non-administrator) token grants no such right either; the drive is fixed and local; and `GetFinalPathNameByHandle` shows no junction, symbolic link or substituted drive. Anything that cannot be read counts as changeable. A folder moved on the same drive keeps its owner, so a user-owned folder moved into Program Files stays unprotected; a copy or extraction made there with administrator rights is owned by Administrators. Otherwise the Run entry is kept and the UAC prompt appears at sign-in. The elevated instance reconciles at start. `RemoveUnsafeStartupTask` first deletes a ClickShade task whose action starts another executable that is missing or not in a protected location (a 1.0 copy in Downloads, say), and the Rules page reports it; a task for another protected copy is left alone. It then replaces a task for this copy's unprotected location with the Run entry and re-registers a task left at below-normal priority, and a task-started `--tray` process raises itself from below normal.

The crash guard installs an unhandled-exception filter and a terminate handler that restore the system cursors first, write a report and minidump to `crash-reports` under the settings folder (the five newest crashes kept), and relaunch with `--after-crash N`. Generations 0 to 2 restart, so up to three crashes in a row are restarted; a crash at generation 3 shows a message instead. A restarted instance that runs for 90 seconds resets its generation to 0. Overlays declare `WDA_EXCLUDEFROMCAPTURE` when the user hides effects from recordings.

## Linux

| Component | Responsibility |
| --- | --- |
| `linux/app.cpp` | GTK pages/controls, palette modes/zoom, startup/reset, tray, shortcuts. |
| `linux/settings.cpp` | Bounded UTF-8 INI, atomic preference save, XDG autostart. |
| `linux/hotkeys.cpp` | Separate X11 connection, passive key grabs, lock-mask variants, conflicts and repeat handling. |
| `linux/x11_engine.cpp` | XI2 input, XFixes cursor observation/hide ownership, composited small ARGB overlays, the screen-read magnifier lens, the Cairo key display, rules and scheduler. |
| `linux/game_detection.h` | Header-only fullscreen-game test (`LooksLikeGame`) over a process's executable, first arguments, parent process names and `WM_CLASS`. |
| `linux/gnome_adapter.cpp` | Dedicated D-Bus transport/context and audio eligibility for the Shell extension. |
| `linux/gnome-extension/` | Experimental nonreactive Shell actors (highlight, clicks, a cloned-layer lens, key labels) and input observation. |

A `--background` or start-minimized launch never shows the window: it waits up to 1.5 s for the XEmbed tray to take the icon, then falls back to a minimized window, and a tray that docks later still hides that window unless the user opened it. Wayland has no XEmbed tray, so the window starts minimized there.

Detect Wayland before `DISPLAY`; an Xwayland connection does not grant global native Wayland input. Unsupported controls remain visibly unavailable. Source builds are distribution-neutral, but each compiled ELF has an explicit library/architecture minimum. GNOME global hotkeys, trails, cursor substitution, a centered lens and generic Wayland parity are not implemented.

The X11 worker has its own wakeable event loop and connection. Current-cursor inversion uses a software overlay and a connection-owned XFixes hide request. Release restores press inversion; an active shake can continue until its own deadline. Every final locator release/pause/error/exit path balances that hide; connection teardown provides a final fallback. Never use global cursor-name replacement as a shortcut, because names can cover distinct app/DPI/animated variants. Multiple master pointers disable this inversion.

X11 shake prepares a bounded cache of the current static cursor, preserves aspect/hotspot and derives its inverted pair from the same scaled alpha image. The cache is built lazily, when a shake starts or while an enlargement is active; a cursor shape change only clears it, and a cache error is published at that point. It differs from KWin's Arrow-only compositor effect.

X11 trails/clicks use bounded small ARGB windows under a compositor. Root substructure events repair stationary stacking; own-overlay notifications are filtered. No continuous idle animation loop is added. The compositor and software cursor overlay determine presentation latency independently of physical pointer coordinates.

The Linux fullscreen rule also pauses only games: the X11 backend and the GNOME companion recognise games run through Steam, Proton/Wine, gamescope, Heroic, Lutris and itch, and other fullscreen windows keep their effects. On X11 `ReadProcess` reads `/proc/<pid>/exe`, `/proc/<pid>/cmdline` (at most 16 KiB and 64 arguments) and up to 16 parent `comm` names once per foreground change, and a `WM_CLASS` or `_NET_WM_PID` change forces a new read. Only the first two arguments are checked for game paths or an `.exe`, so a player opening `setup.exe.mp4` or a file in a later argument is not a game. A `ConfigureNotify` on the foreground window arms one re-check 60 ms after the first event, so a window drag does not flood the rules. A `RESOURCE_MANAGER` change on the root window re-reads `Xft.dpi` and rescales every effect.

On X11 a hidden pointer is a cursor image whose every pixel is transparent, cached per cursor serial. It clears every pointer effect, the spotlight and lens included, except during a typing hold: the pointer went from visible to hidden within 1.5 s of a key press the engine observed, and the hold lasts until the pointer shows, another rule applies, or 3 s after the last key. Key presses are observed only while keyboard sounds or the key display are on, so there is no hold otherwise. Key sounds and the key display use `RulesAllowKeys`, every rule except the hidden pointer, and `LinuxAudio` keeps separate mouse and keyboard allowances, so revoking one releases only that group's voices and queued starts.

The X11 lens reads its source square with `XGetImage` from the root window, so it must never overlap that square: it always sits beside the pointer and moves further away when a monitor edge would force an overlap. It draws the last captured cursor image into the magnified view and reads the screen again only when the pointer moves, the pressed artwork or a setting, monitor, scale or cursor shape changes, or 33 ms have passed, never at the animation rate. Its source square is capped to the on-screen part of the pointer's monitor, so a large lens on a small or high-scale monitor shows a smaller square, magnified more than the chosen zoom, rather than reading a neighbouring monitor. Breathing has its own 30 Hz deadline and draws into a window sized for the full radius, so the window size stays constant. The X11 key display subscribes to raw key presses and releases only while enabled, reads modifier state from XKB, resolves typed characters with `XkbLookupKeySym`, and draws its rows with Cairo, fading each row on its own; row measurements are cached and taken again when a row changes or the panel is drawn on a monitor of a different width. Its gate skips the transparent-cursor rule. The X11 spotlight is one monitor-sized ARGB window backed by a server-side pixmap: a move redraws the old and new circle in the pixmap and copies that rectangle to the window in one request. The GNOME lens is a `Clutter.Clone` of the window layer inside a clipped chrome actor, which cannot contain the Shell's own chrome or ClickShade's actors; the GNOME key display builds rows of St keycaps, with the stroke rules (typed rows, Backspace, repeat counts, row limit) shared as pure functions in `core.js`.

Xlib error handlers are process-wide. The shared lifecycle mutex in `linux/x11_errors.h` serializes renderer handler install/uninstall with the entire temporary shortcut registration trap; error callbacks never lock it.

X11 shortcuts use explicit passive grabs, not input injection. Grabs include current lock-mask combinations; repeat releases are deduplicated and conflicts roll back. Ctrl+Alt+function-key/Backspace server combinations are rejected. The Linux restore default is Ctrl+Shift+F10; Windows uses Ctrl+Alt+F10.

The GNOME bridge coalesces settings wakes to one pending GLib source and attempts bounded deactivation from worker cleanup, including Stop during initial connection. It sends `SetActive` with the master switch on every settings change, over the session connection that stays open for the app's lifetime, so the switch and **Pause and restore** reach the Shell at once. It calls `GetStatus` without a fixed reply type and accepts `(bbss)` or `(bbsss)`, ignoring a capability text. `AllowedChanged` gates keyboard sounds and, together with `MouseAllowedChanged`, click sounds; without the second signal (a 1.0 extension) `AllowedChanged` gates both. Audio file loading rejects non-regular inputs through a nonblocking open plus same-descriptor validation. The PulseAudio stream starts corked, uncorks for a voice and corks again 400 ms after the last voice ends, with no timer source; with neither sound group ready the connection is closed and a preview reconnects.

The GNOME extension observes available captured events plus sampled button state. Very short unsignalled clicks can be missed between samples. It watches the config directory for atomic replacements, keeps actors nonreactive, publishes audio pause eligibility, and synchronously removes actors/timers/signals/watches/D-Bus exports on disable. It draws nothing until `SetActive(true)` and then watches the caller's unique bus name, pausing when that name leaves the bus; only that name survives a disable/enable cycle such as the lock screen. Pointer sampling runs only for pointer features, and breathing repaints on its own 30 Hz deadline.

## Privacy and limits

Preferences, user-directed exports/backups, a single pre-import backup, an opt-in startup entry and, after a crash, the `crash-reports` folder (up to five `.txt`/`.dmp` pairs plus `last-crash.txt`) are the intended persistent app data. The temporary cursor folder lasts only as long as the instance that wrote it; after a hard exit, the next start of an unelevated instance removes it. There is no application activity/debug logger, telemetry, network endpoint, automatic update checker, input recording or screenshots. Errors are shown on screen. In-memory counters used by explicit developer checks are not persisted or shown as a diagnostic panel.

Foreground process names and image paths are obtained through limited OS metadata APIs for matching rules and the fullscreen-game test, which on Windows also reads Game Bar's game list from the registry and on Linux reads `/proc/<pid>/exe`, `cmdline` and, on X11, parent process names. None of it is stored. This is not process-memory access. Out-of-context accessibility hooks are used on Windows; claiming "no hooks of any kind" would be inaccurate. There is no anti-cheat bypass or universal certification.

## Build and release invariants

Build both binaries after source/resource edits. `ClickShade.exe` resolves its static DLL imports from System32 only (`DependentLoadFlags` = `LOAD_LIBRARY_SEARCH_SYSTEM32`, honored from Windows 10 version 1607), so a DLL planted beside it in a writable download folder is ignored. MSVC builds set it with `/DEPENDENTLOADFLAG:0x800`; MinGW and Zig builds get it from the load configuration defined in `src/app.cpp`, and `tools/build_zig.py` fails the build when the linked image lacks it. Comctl32 v6 still comes from WinSxS through the manifest. The packager uses an explicit source manifest, rejects stale/wrong-architecture applications, excludes build debris and compiled tests, preserves Linux permissions, and checks every ZIP entry's SHA-256. CI additionally verifies both build revisions against the checked-out tag.

Test source is included for reproducibility. Test executables require an explicit developer build; interactive suites require `--run` and an isolated desktop and are not registered with CTest. CI runs every registered headless suite through `ctest` on both platforms: on Windows the layout geometry, frame pacing, shake, audio decoder, audio streaming, settings profile, shortcut parser, key-display label and pointer lead suites; on Linux the shared layout, pacing and shake suites plus settings, audio files, the GNOME bridge queue, shortcut syntax and fullscreen game detection. `linux/build.sh --test` and `tools/build_linux.py --test` keep their own lists of the same eight Linux suites. Do not promote Wine/Xvfb results to native Windows/GPU/game certification or GNOME mocks to real compositor coverage.

## Profile transaction

Windows and Linux export complete platform-labelled format 2 snapshots and still
accept complete format 1 snapshots from preview builds, applying the same upgrades
as a settings file without a version. Import requires a bounded regular file,
valid Unicode, the correct platform/version, every schema field, valid ranges and
compatible shortcuts. Unknown/duplicate/incomplete values are errors; preference
loading for ordinary upgrades remains tolerant of missing new keys.

The GUI parses first, asks to replace the current profile, saves one pre-import
backup, applies shortcut registrations transactionally and atomically saves the
candidate. Failure retains or restores working preferences/bindings. Actual
startup registration is a machine choice and is not imported. Only after commit
does the GUI refresh runtime/theme/controls. Backup/export paths are not activity
history; external cursor/audio files are not copied.
